# TODO.md 管理スキル

現在のディレクトリの `TODO.md` を作成または更新する。

## 手順

1. **必ず最初に** `date '+%Y-%m-%d'` を実行し、実際の今日の日付を取得する。システム情報やセッション文脈の日付は信用しない。
2. ディレクトリ内の状態を走査し、現在の進捗・未完了の作業・問題点を把握する
3. 既存の `reading_list.md` があれば読み込み、1ページを読むのに2分かかるとして計算する。なければ無視する。
4. 既存の `TODO.md` があれば読み込み、現状と照合する
5. `$ARGUMENTS` にユーザーからの追加条件（期限変更、優先度指定、新タスクなど）があれば反映する
6. 以下のフォーマットに従い `TODO.md` を生成・更新する（「最終更新」には手順1で取得した日付を使う）

## TODO.md フォーマット

```markdown
# TODO - [プロジェクト/ディレクトリ名]

最終更新: YYYY-MM-DD

## タスク

### タスク名
- **ステータス**: 未着手 | 進行中 | 完了 | ブロック中
- **優先度**: 高 | 中 | 低
- **期限**: YYYY-MM-DD | なし
- **見積もり時間**: Xh
- **依存関係**: なし | タスク名A, タスク名B
- **ゴール**:
  - 達成すべき状態の記述
- **メモ**:
  - 補足情報や注意点

---

(タスクごとに --- で区切る)

## 完了済み

### 完了したタスク名
- **完了日**: YYYY-MM-DD
- **メモ**:
  - 最終的にどう解決したか等の引き継ぎ情報
```

## ルール

- **ステータス**は4種: 未着手、進行中、完了、ブロック中
- **優先度**は3段階: 高、中、低
- **見積もり時間**はそのタスクに集中して取り組んだ場合の所要時間
- **依存関係**は同一ディレクトリ内のタスク間の順序制約を示す。依存がなければ並列実行可能
- **完了済みセクション**は直近のもののみ残す（コンテキスト引き継ぎ用。古いものは削除）
- タスクの粒度は「1回の作業セッションで着手〜完了できる」サイズを目安にする
- ディレクトリの走査だけでは判断できない外的条件（期限、面接日程、締切変更など）はユーザーの指示を忠実に反映する
- このディレクトリがプログラミングに限らない（研究、就活など）場合もある。内容に応じた適切なタスク記述をする
- 詳細な実装手順やコード片は含めない（作業セッションが判断すべき）

## 使用例

```
/todo                              → ディレクトリを走査して TODO.md を生成/更新
/todo 面接が4/5に決まった、優先度を上げて  → 外的条件を反映して更新
/todo 論文の締切が4/15に延期された        → 期限を変更
/todo 新規: レビュー対応 期限4/10 優先度高  → 新タスクを追加
```
